# Marble Labyrinth — Stage 1 Prototype

An original Android-first Godot 4.6.3 3D physics puzzle. The player tilts a miniature mechanical labyrinth and guides a real `RigidBody3D` marble through wind, magnetic and trap mechanisms.

This repository is a playable development prototype. It is not a signed Android build and has not been published to Google Play.

## What is implemented

- A real rolling marble with continuous collision detection, tuned friction, low damping and physical inertia.
- A physics-synchronised tilting `AnimatableBody3D` board with deck and wall collision shapes.
- Local-space wind and magnetic forces that continue to behave correctly while the board is tilted.
- Reset trap, fall recovery, goal trigger, timer and full level reset.
- Procedural workshop styling: layered dark-metal deck, brass rails and fasteners, polished marble, mechanical vents and coils, emissive hazard rings, warm/cool lighting and shadows.
- Android gravity-sensor input with calibration, left-side touch tilt and right-side orbit camera.
- Switchable Auto, Touch and Sensor modes from the HUD.
- Windows keyboard, mouse orbit and mouse-wheel zoom.
- Level geometry isolated in a data file so later levels can reuse the controller and presentation.

No paid or third-party art assets are used. The current geometry and materials are generated by the project.

## Controls

| Platform | Action | Control |
| --- | --- | --- |
| Windows | Tilt board | Arrow keys |
| Windows | Orbit camera | Hold right mouse button and drag |
| Windows | Zoom | Mouse wheel |
| Android | Tilt board | Phone motion sensor or drag on the left half |
| Android | Orbit camera | Drag on the right half |
| Both | Change Auto/Touch/Sensor mode | **Control** HUD button or `G`/`M` |
| Both | Calibrate sensor | **Calibrate** HUD button or `C` |
| Both | Reset level | **Reset** HUD button or `R` |

For sensor play, hold the phone in a comfortable neutral position and press **Calibrate**. Auto mode uses touch input while the left side is being dragged and otherwise uses the motion sensor when one is available.

## Run and verify

Use the standard Godot 4.6.3 editor build:

```bash
godot --path . --editor
```

Press **F6/F5** in the editor, or run directly with:

```bash
godot --path .
```

The project has headless checks suitable for Linux or Codex Cloud:

```bash
godot --headless --path . --editor --quit
godot --headless --path . --fixed-fps 60 --quit-after 180
godot --headless --path . --fixed-fps 60 --script res://tests/smoke_test.gd
```

The smoke test verifies scene loading, a live rigid marble, deck and wall collisions, keyboard tilt, physical movement, wind force, magnetic attraction, trap/reset and the goal.

## Project layout

```text
project.godot                  Project settings and main-scene entry point
scenes/main.tscn               Canonical game scene
scripts/main.gd                Input, physics, presentation and game flow
scripts/levels/level_01.gd     Level 1 layout and obstacle parameters
tests/smoke_test.gd            Headless integration test
```

New levels should provide the same data shape as `level_01.gd`. This keeps layouts separate without introducing a level manager before the game needs one.

## Android work still requiring a physical phone

- Confirm gravity-axis direction in landscape orientation on the target devices.
- Tune neutral calibration and sensor sensitivity for different mounting angles.
- Test multi-touch while tilting and orbiting at the same time.
- Measure frame rate, thermals, battery use, UI safe areas and readability on small screens.
- Test pause/resume, focus loss and device rotation behavior.
- Configure Android export templates, API level, package ID and an unsigned/debug export preset.
- Create and protect release signing material outside Git only when release preparation begins.

Do not use an Android emulator for this project, commit signing keys, or publish to Google Play without the owner's explicit approval.
